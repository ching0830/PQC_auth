PQ-RBBC v2.31 CAP Unique-Mask Reduction Candidate

Checkpoint date: 2026-09-04
Game: pq-rbbc/cap/unique-committed-mask/v1
Target: one canonical admissible c_r cannot bind two distinct 576-bit masks.

Disposition: the reduction is specified and its diagnostic terms are numeric, but the current fork does not meet the prerequisites needed to instantiate it. In particular, the final CAP verifier and the NIST-III/Shorter proof-of-work layer are missing. The raw mixed-tree challenge term is only 182 bits even before query loss. Unique-mask and CAP-security claims remain false.

1. Unique-mask game

The adversary receives the frozen CAP profile and access to the six-domain ROM oracle. It wins by outputting one canonical c_1, two distinct masks r_0 != r_1, one common ordered full-value oracle transcript, and two accepted opening-relation continuations proving that the same commitment prefix opens to those masks. Canonical parsing, oracle domain separation, and the exact mixed tree shapes are part of the game.

This definition intentionally requires accepted final continuations. A commitment produced by the deterministic functional fixture is not, by that fact alone, an admissible adversarial commitment.

2. Conditional reduction

Assume a deterministic Definition-10 extractor Ext_1 for the opening relation, with failure probability epsilon_ext, and strict injective serialization/domain parsing. Given a winning unique-mask adversary, run Ext_1(Q_CAP,c_1) once. Its output cannot equal both distinct masks. Select one of the two accepted continuations uniformly and use it in the Definition-10 knowledge-soundness game. With probability at least one half, the selected public opening value differs from the extractor output. Conflicting oracle responses or parser aliases are diverted to their respective collision/ambiguity games.

Adv_uw(A) <= 2 * Adv_ext(B)
             + Adv_oracle_collision(C)
             + Adv_serialization_ambiguity(D).

The factor two is conservative and avoids assuming that the two continuations can both be submitted in one knowledge-soundness experiment. If a reviewed multi-opening formulation permits the reduction to choose the mismatching continuation directly, the factor can be tightened.

4. Exact mixed-tree accounting

The production profile has two trees with N=2^12 and sixteen trees with N=2^11. Therefore:

sum_e log2(N_e) = 2*12 + 16*11 = 200
Pr[one hidden leaf per tree] = product_e (1/N_e) = 2^-200

d = 2, tau = 18
Pr[invalid degree-2 relation passes raw challenges]
    = product_e (d/N_e) = 2^18 / 2^200 = 2^-182.

Table 2 of the source paper assigns approximately 13.9 bits of total proof-of-work to the NIST-III/Shorter TCitH parameter set. The current fork implements neither that proof-of-work nor the final challenge/opening verifier. Consequently the paper's parameter theorem does not transfer. It is not sound to silently add 13.9 bits to the fork.

5. Diagnostic ROM terms

With 386-bit oracle outputs (2*lambda, lambda=193), the directly identifiable terms are:

T_guess(q_H)     = q_H / 2^386
T_collision(q_H) = q_H^2 / 2^387
T_missing(q_H)   = q_H / 2^200
T_degree(q_H)    = q_H / 2^182.

The consistency hash parses the 2,048-bit vector as 11 coefficients over GF(2^193), so one evaluation has collision probability at most 10/(2^193-1). Two independently derived, distinct nonzero points give the diagnostic bound epsilon_uuh <= (10/(2^193-1))^2. Across 18 trees the union term is q_H * C(18,2) * epsilon_uuh. This calculation assumes the consistency-point oracle behaves as the required random source; it is not a concrete Anemoi proof.

6. Qualification consequence

At q_H=1, the raw degree term already exceeds the target 2^-192. Thus the current commit-only profile cannot be qualified at 192 bits from the mixed-tree challenge schedule alone. A safe resolution must freeze and review one of:

  1. the paper's proof-of-work and final TCitH proof semantics in the exact fork;
  2. a strengthened tree/challenge schedule with fresh performance and size evidence; or
  3. a lower, explicitly accepted security target supported by a complete proof.

Choosing among these changes the cryptographic profile and is outside this authoring checkpoint.
