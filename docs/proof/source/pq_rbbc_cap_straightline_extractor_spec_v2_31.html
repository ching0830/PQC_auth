2. Oracle transcript model

Q_CAP is an ordered sequence of full query/response values. A record contains the sequence index, one of the six CAP domain identifiers, the complete canonical tuple-encoded input, the declared output width, and the complete canonical output. The domains are seed_derive, seed_commit, tape_expand, h1, consistency_points, and h2. Digest-only records are not extractor input.

The parser rejects non-contiguous ordering, unknown or aliased domains, wrong output widths, malformed tuple framing, noncanonical hex, nonzero unused high bits, and conflicting responses to the same query. The request-binding oracle H_RBBC is outside Q_CAP.

3. Canonical prefix parsing

3.1 First commitment c_1

The strict parser accepts exactly:

magic || u16le(version=1) || profile_sha256 || salt[0] || salt[1]
      || h2 || u32le(correction_bytes) || alpha
      || repeated(delta_P[e] || delta_Mhat[e]), e=2..18

Field elements are 25-byte little-endian GF(2^193) encodings, hash values are canonical 386-bit strings, alpha and every delta_Mhat are 386 bits, and every delta_P is 2,048 bits. The correction block is checked byte-for-byte against the preimage of h1.

3.2 Candidate second commitment c_2

The current implementation exposes delta_x as a 1,472-bit integer but did not freeze a serialized c_2. For executable test vectors only, this packet defines a domain-specific candidate encoding:

"PQRBBC-CAP-APPEND-CANDIDATE-V1" || u16le(1)
      || profile_sha256 || u32le(1472) || delta_x[184 bytes]

This encoding must not be treated as a production format until a later contract explicitly freezes it.

4. Extractor algorithms

4.1 Shared recovery

Recover(Q_CAP, c_1):
  1. Strictly parse Q_CAP and c_1.
  2. Find the unique h2 query whose output is c_1.h2; recover h1 and 18 xi fields.
  3. Find the unique h1 query whose output is h1; recover all leaf commitments
     and correction data. Reject a profile, tree-size, degree, index, or
     correction mismatch.
  4. Recover the consistency points from their unique full-value oracle query;
     reject zero, repeated, or wrong-width points.
  5. For every leaf commitment, find its unique seed_commit preimage and the
     corresponding tape_expand query. A missing leaf makes that tree incomplete;
     multiple preimages are an ambiguity failure.
  6. For each complete tree e, XOR the tapes to obtain plain[e]. Apply
     delta_P[e] and delta_Mhat[e], recompute alpha, reconstruct the extension-
     field masks, and compare the complete xi[e] preimage committed by h2.
  7. Reject if no candidate survives or if surviving trees give distinct
     2,048-bit witnesses. For the production vector, require at least one
     complete degree-13 tree and one complete degree-12 tree.
  8. Return the unique witness P'(0).

4.2 Ext_1 and Ext_2

Ext_1(Q_CAP, c_1):
    witness = Recover(Q_CAP, c_1)
    return witness[0..575]

Ext_2(Q_CAP, c_1, c_2):
    witness = Recover(Q_CAP, c_1)
    delta_x = StrictParseCandidateAppend(c_2)
    r = witness[0..575]
    x = witness[576..2047] XOR delta_x
    return (r, x)

Neither function has a statement, relation instance, final proof, secret root seed, or prover randomness parameter. There is no rewinding and no quantum-query measurement step.

5. Honest-vector correctness

For the frozen production generation transcript, every committed leaf seed and tape query is present. XORing the tapes reproduces each tree's constant coefficient. The correction values make the 18 corrected constant coefficients identical. Recomputing the two-point polynomial hash and extension-field masks reproduces alpha and all 18 xi inputs to h2. Consequently the executable candidate returns the commitment's derived 576-bit mask, and after applying the candidate c_2, returns the deterministic 1,472-bit test witness.

This is an implementation/vector statement. It does not quantify over adversarial commitments accepted by a verifier.
