# 第六堂：一張票券為什麼需要多種隨機資料

日期：2026-09-14。所屬階段：2／必要安全概念。
接續 [第五堂](05_HASH_AND_TRACE_ENCRYPTION_zh-TW.md)，沿小明取得兩張票券，說明持票者秘密、
序號與加密隨機資料的用途。本堂附一段獨立 Python 示範；逐模組閱讀仍留在後續階段。

## 先分清楚三種要求

「隨機數」也常稱為「亂數」。在程式裡，它可以是一個整數，也可以是一串 bytes。
本課需要分開看三件事：

- 不可預測：不知道秘密狀態的觀察者，不應能有效猜中所需的秘密資料。
- 避免重複：同一用途需要新的值，不能刻意把先前用過的值再拿來使用。
- 是否保密：取決於用途；資料由亂數產生，不表示它一定不能公開。

例如 `1、2、3、4` 可以互不重複，下一個值卻很好猜。把這種序列直接當成秘密，
不會因為每次改值就變安全。隨機取樣也不等於數學上保證絕不碰撞；需要配合適當範圍與協定規則。

## 小明取得第一張與第二張票券

假設兩張票券對應相同註冊身分、相同共同設定，而且都通過各自的發行程序。
表中的「第一份／第二份」只是教材名稱，不是真正取樣結果或傳送的文字。

| 資料 | 第一張票券 | 第二張票券 | 是否對 FGS 公開 |
| --- | --- | --- | --- |
| 持票者秘密 `k_hold` | 新取樣的第一份秘密 | 再取樣一份新秘密 | 秘密留在裝置，票券只出示相應摘要 `h` |
| 票券序號 `sn` | 新取樣的第一個序號 | 再取樣一個新序號 | 是，出示票券時可見 |
| 加密隨機資料 `e` | 為第一張票券取樣 | 為第二張重新取樣，遵守不重用要求 | 屬秘密見證，不隨票券公開 |

這裡談的是發行另一張票券。合法重試同一次接入時如何使用原票券，另由接入規格處理；
本堂沒有要求每次網路重送都重新發行票券。

## 1. 持票者秘密：支持認證，避免固定摘要

小明的裝置用秘密算出 `h = H_hold(k_hold)`。如果兩張票券重用相同秘密，就會出現相同 `h`，
觀察者可利用這個共同值連結兩張票券。它顯示共同的綁定值，不直接證明註冊身分。

核心定義要求每張票券使用新的 256-bit 持票者秘密，即 32 bytes。秘密需要難以猜中，
也需要在裝置上受到保護。新取樣可以避免刻意重用固定秘密，但不單獨建立整體不可連結性。

## 2. 序號：辨認票券，不承擔秘密認證

核心使用新取樣的 128-bit 序號，即 16 bytes。它同時出現在票券可見欄位與追責密文的明文裡，
使開啟端能核對解出的序號是否符合這張票券。系統的票券使用紀錄也會用到序號及摘要。

序號可以在出示票券時公開；它不是用來讓持票者證明秘密的資料。重複出示同一張票券，
原序號仍然相同，可以被辨認。

產生一個新序號不會自動完成一次性使用限制。成功使用後的記錄與拒絕再次建立連線，
仍需要前面提過的持票者認證與票券消耗狀態。隨機序號的碰撞機率也不是零。

## 3. 加密隨機資料：參與隱藏身分的計算

在本專案的追責加密構造中，`e` 參與產生密文，以及保護「註冊身分與序號」的遮蔽資料。
它是有格式限制的隨機向量：目前 profile 要求 6688 個 bit 中恰好 128 個為 1，並依規定分布取樣。
這個欄位的程式名稱 `error` 是密碼學構造中的名稱，不表示程式出了錯。

依核心 N1–N5 與 reference `_derive_trace()` 可推得：在相同開啟公鑰和共同設定下重用 `e`，
會使部分密文結構與遮蔽資料重複；改換序號或持票者秘密不能消除這項重用。
核心 trace privacy 定理明列不重用 `e` 的前提。

`e` 也不能當成公開序號：按這個構造，知道它及公開資料即可重算遮蔽資料，進而還原受保護明文。
公開票券中的密文與公開加密時的秘密見證，是不同事情。

第四堂的盲化也需要另外的隨機資料；本表集中介紹三個票券相關用途，不是協定全部亂數的清單。
各欄位應按各自方案取樣與使用，不能把同一份 bytes 直接塞入所有欄位。

## 一小段 Python：產生秘密與序號

Python 隨附的 `secrets` 模組提供適合秘密資料的亂數工具，使用作業系統提供的安全亂數來源。
`token_bytes(n)` 產生指定 n 個 bytes。這裡的一個 byte 是 8 個 bit；byte 值介於 0 到 255。
參考 [Python 官方 secrets 文件](https://docs.python.org/3/library/secrets.html)。

```python
import secrets

holder_secret = secrets.token_bytes(32)
ticket_serial = secrets.token_bytes(16)

print(len(holder_secret), len(ticket_serial))
```

`import secrets` 載入 Python 已附帶的模組，不需要另外安裝。
兩次呼叫分別產生秘密與序號；`len()` 計算 bytes 長度，印出 `32 16`，沒有印出秘密內容。
此片段只示範基本取樣，不建立完整票券，也不產生 `e`。`e` 的特定格式與分布需要另外的取樣程序。

Python 的 `random` 預設產生器主要供模擬等用途，不適合產生密碼學秘密；本課直接用 `secrets`。
這個區分指預設 `random.Random` 與相關函式，並非否定同模組中使用作業系統亂數的 `SystemRandom`。
參考 [Python 官方 random 文件](https://docs.python.org/3/library/random.html)。

## 讀目前程式時要注意的區別

[reference model](../../src/pq_rbbc_reference.py) 的 `reference_fixture()` 使用固定字串產生
固定秘密、序號及其他測試資料。`sample_weight_error()` 也明寫是 deterministic fixture sampler。
「fixture」在這裡是準備好的測試資料；固定輸入方便不同次測試重現同一結果。

因此，這些函式的用途是協助核對計算與綁定。`build_honest_instance()` 接收呼叫端給的資料，
也不能因名字含 honest，就推論呼叫端已使用安全亂數。

這給未來修改程式一個具體判準：**符合長度或格式，不足以證明值是不可預測地取樣得到的。**
正式使用者流程需要正確的亂數來源、取樣方法與秘密管理；本堂沒有把測試 fixture 改成正式發行器。
