把知道身分、看見使用、開啟身分分開

角色分離限制單一 compromise 的影響；門檻與授權限制需要多少方合作。

Operator提出共同 policy、epoch、serving rules
→
FAC／Governance認證 configuration 與 issuer grant
↓ 分派彼此獨立的 key roles 與權限 ↓

HNCC：發行能力

知道註冊 rid、issuance session、quota

不應取得：ticket 使用紀錄、OA threshold。

FGS：接入能力

看見ticket、時間、位置、session、consumption state

不應取得：註冊 rid、issuer／opening secret keys。

OA：開啟能力

持有彼此獨立的 shares；至少 tₒ 份才可重建

不應取得：任意查詢介面；仍須有效 case authorization。

LEO／FLEO：只中繼或做明確的輕量檢查，不保存 issuer、FAC 或 OA secret keys。
HNCC + FGS身分資料與完整接入 metadata 集中，traffic correlation 風險上升。
FGS + tₒ OA看到每張票券的一方同時取得開啟能力，FGS anonymity 崩解。
授權 + tₒ OA同一控制域可自行批准再解密，兩道治理門失去獨立性。
角色分離不會消滅共謀：它界定攻擊者必須控制哪些 key roles、多少 shares，以及哪些紀錄應被稽核。
