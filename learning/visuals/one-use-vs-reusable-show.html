一張用一次，或一份憑證出示多次？

兩種模型都能追求匿名，但使用次數、在線證明與共享狀態的責任不同。

One-use ticket batch

預先取得多張不同票券，每次 initial access 消耗一張。

WalletT₁ · T₂ · T₃
→
Access 1出示 T₁
→
FGS stateT₁ = CONSUMED
  • 下次 initial access 改用 T₂。
  • 嚴格一次性需要原子共享狀態。
  • 代價是票券庫存、補發與 crash ambiguity。

Reusable anonymous Show

保留一份 credential，每次產生不同的零知識 presentation。

Credential C長期保存
→
Show 1π₁，fresh r₁
→
Show 2π₂，fresh r₂
  • π₁、π₂ 應無法被直接連回同一 holder。
  • 每次需執行新的 randomized ZK Show。
  • 原生不限制使用次數；quota 需額外機制。
直接重送目前固定票券 T：是可連結的 ticket reuse，不是 reusable anonymous Show。
